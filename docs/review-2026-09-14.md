## 2. 模组做什么

两个方块，都实现 `IFluidHandler`，每 tick 向邻接方块 `fill`：

1. **无限水**（`BlockInfiniteWater` / `TileInfiniteWater`）
   - 永远是水，`Integer.MAX_VALUE`，无配置、无 NBT
2. **无限液体**（`BlockInfiniteFluid` / `TileInfiniteFluid`）——当前主功能
   - 手持容器右键设流体：Forge `FluidContainerRegistry`、GT6 `gt.tank`、IC2 `Fluid`、OpenBlocks `tank`
   - 空手右键看状态；潜行空手循环速率：`65536 / 262144 / 1048576 / 4194304 / 16777216` mB/t
   - 破坏时自定义 NBT 写入掉落物，放置时读回

配方：炼药锅 + 铁锭。检测到 IC2 精炼铁时，**只**给无限水换材料（见问题 1）。

构建：GTNH Gradle 脚本，Forge `10.13.4.1614`，JDK 8 目标，`enableModernJavaSyntax = true`（Jabel）。

## 4. 按文件审查

### 4.3 `config/ModConfig.java`

写入三个键：

| 键 | 默认 | 实际是否被读 |
|----|------|----------------|
| `EnableInfiniteWater` | true | 是，控制配方注册 |

### 4.5 `registry/ModBlocks.java`

### 4.12 `block/BlockInfiniteFluid.java`

2. IC2 `Fluid`
3. OpenBlocks `tank`（PR #15）

未覆盖 `IFluidContainerItem`（BuildCraft / EnderIO / 不少 GTNH 罐子）。

### 4.13 `item/ItemBlockInfiniteFluid.java`

客户端 tooltip。会把旧 NBT（`OutputFluid` + `OutputRate`）一次性升级成 `InfiniteFluidStack`。文案写死中文，与方块聊天的英文不一致。`保存量: fs.amount mB` 对玩家几乎无意义（那是速率被写进 FluidStack.amount 的副作用，不是储量）。

### 4.14 `tileentity/TileBase.java`

- `writeToNBT` / `readFromNBT` **不调用** `writeCustomNBT` / `readCustomNBT`
- `getDescriptionPacket` 发整份 `writeToNBT`
- `isPowered()` 无人调用
- `onBlockBroken()` 默认只 `markDirty`

自定义 NBT 钩子形同虚设，子类必须自己 override 世界存档路径。这是 NBT 分叉的根。

### 4.15 `tileentity/TileInfiniteWater.java`

每 tick 对 `VALID_DIRECTIONS` 邻接 `IFluidHandler` 填 `INFINITE_WATER`（静态、`Integer.MAX_VALUE`）。被抽也给水。无 NBT。方向枚举用对了（不含 `UNKNOWN`）。

### 4.16 `tileentity/TileInfiniteFluid.java` — 核心

**`updateEntity`（`66e2a4b` 已修）：** 每个方向 `new FluidStack(outputFluid, outputRate)` 再 simulate + fill。不再共用 `Infinite_Fluid`、第一面改 `amount` 导致后面几面少出。

方向仍用 `ForgeDirection.values()`，含 `UNKNOWN`（offset 全 0，对自己 fill，返回 0，无害但多余）。

**主动 fill 受 `outputRate` 限制；`drain` / `drain(maxDrain)` 不看速率**，管道来抽给多少要多少。push 与 pull 行为不一致，属设计问题。

**`canDrain` 用 `==` 比 `Fluid`。** 一般 Fluid 是单例，通常没事。

**NBT 两套路径：**

| 路径 | 谁调用 | 写什么 | 读什么 |
|------|--------|--------|--------|
| `writeToNBT` / `readFromNBT` | 世界存档、描述包 | `InfiniteFluidStack` + `OutputRate` | 先用 `fs.amount` 当速率，再被末尾 `OutputRate` 覆盖 |
| `writeCustomNBT` / `readCustomNBT` | 掉落 / 放置 | 同上 | 读 `InfiniteFluidStack` 时 `outputRate = fs.amount`，**不**把 `Infinite_Fluid.amount` 拨回 `OutputRate` |

Issue #11（重进存档速率还原）靠 `readFromNBT` 末尾 `if (hasKey("OutputRate"))` 兜底活着。`readCustomNBT` 没有同等拨回，物品 NBT 两字段不一致时，放下后速率和输出量可能对不上。

`setOutputFluid` 两端都 `markBlockForUpdate`；`cycleOutputRate` 有 `!isRemote`。

`getTankInfo` 用 `Infinite_Fluid` + 容量 `Integer.MAX_VALUE`。`Infinite_Fluid.amount` 在 `updateEntity` 修好后不再被每 tick 改写，但 NBT 读入仍可能把它设成速率值。

注释掉的 20-tick 节流已随 `66e2a4b` 删掉。

### 4.17 文档与文案

- `README.md` / `READMEen.md`：仍是示例 Mod。包名 `com.example.infinitewater`，贴图 `infinite_water.png`，只提无限水，不提无限液体、速率档、GT6/IC2/OB、NBT 掉落。
- lang 只有方块名和创造标签。聊天、tooltip 均硬编码。
- `mcmod.info` description 未提无限液体。

## 5. 已讨论、结论为「先不动」的项

### 每 tick `new FluidStack` 与 GC

每块每 tick 最多 6 个短命小对象（`Fluid` 引用 + `int`）。100 个方块量级约每秒一万次分配，相对 1.7.10 每 tick 自产的 `AABB`/`Vec3` 可忽略。真热的是邻接管道/储罐的 `fill()`，不是这次分配。

原 bug 不是「没复用」，是循环结束才把 `amount` 拨回去，且不少 1.7.10 `fill()` 会改传入的 `FluidStack`、极少数会留引用。每面一份是正确性选择。

零分配写法（每面开头重置 `Infinite_Fluid.amount`）可以，前提是邻接 `fill()` 不长期握该实例。现在不必换。不要上对象池。

### 20-tick 节流

已从 `updateEntity` 删除。不要加回去，除非 profiler 证明 `fill()` 热。

## 6. 问题清单（按会不会真坏）

### 必修

**1. IC2 吃掉无限液体配方**  
`ModRecipes` 成功注册 IC2 水方块配方后 `return`。GTNH 下液体方块合成不出来。  
修法：去掉 `return`，两个配方分开注册。液体方块要不要也用精炼铁另说。IC2 物品名建议改 ore dict `ingotRefinedIron`。

**2. NBT 两套路径分叉**  
`TileBase.writeToNBT` 不调 custom。世界存档与掉落物逻辑已分叉。Issue #11 同类还会再来。  
正确做法：流体只存名字（或 FluidStack amount=0），速率只存在 `OutputRate`。两套读写共用一个方法。旧存档（`OutputFluid` / 把速率写进 `fs.amount`）留一截兼容。

**3. 破坏掉落路径**  
`getDrops` 空 + `breakBlock` 自 spawn。确认创造模式、活塞、爆炸、机械破坏是否符合预期。创造模式当前会掉带 NBT 的方块。

### 行为不一致 / 半成品

**4. 配置是假的**  
只接了配方开关。`infiniteWaterRate`、`redstoneControl`、`isPowered()` 全没接。要么接上，要么删掉。`infiniteWaterRate` 的语义（tick 间隔）与现行模型（mB/t）冲突，不能直接当速率用。

**5. 两个方块定位不清**  
无限水：无限吞吐、永远水。无限液体：配方更贵（8 铁 vs 4 铁+5 锅），默认输出反而更小（64k vs MAX）。需要 README 写清，或产品上决定是否淘汰/合并。

**6. 非流体物品右键无反馈**  
挥手、没聊天。空桶不会清空流体。

**7. 中英混杂**  
tooltip 中文，聊天英文。应走 lang 文件。

**8. 未识别 `IFluidContainerItem`**  
比继续堆 NBT key（`gt.tank` / `Fluid` / `tank`）覆盖面更大。BC / EnderIO / 部分 GTNH 罐子走这条接口。

### 正确性边角

**9.** `ForgeDirection.values()` → 应 `VALID_DIRECTIONS`（无限水已经用对）。  
**10.** `drain` 不限 `outputRate`：push/pull 不一致，要产品拍板。  
**11.** `canDrain` 用 `==` 比 Fluid，更稳比 `fluidID` / `getName()`。  
**12.** `setOutputFluid` 客户端也 `markBlockForUpdate`。  
**13.** `readCustomNBT` 后未 `markDirty`。  
**14.** IC2 精炼铁物品名可能从未命中，应 ore dict。

### 卫生（可删）

**15.** 空壳：`NetworkHandler`、`ModEntities`、`ModItems`。`ClientProxy` 可留空。  
**16.** `ModConfig`「未来扩展」注释。  
**17.** `BlockInfiniteFluid.displayName`。  
**18.** README / `mcmod.info` 与代码不对齐。

### 建议别做

- 为 `new FluidStack` 上对象池或缓存
- 给无限水加 GUI / 速率档（除非明确要统一成一种方块）
- Mixin / 自定义网络包（现有描述包够用）
- 流体识别「适配器框架」（if 链 + `IFluidContainerItem` 足够）
